## OAuth2 与多用户结论

- OAuth2 只解决“怎么拿 token”，不解决“连接/授权态被谁复用”。若 mcp-client 仍是进程级单连接/单授权态，OAuth2 后仍会串号。
- 真正隔离需要 per-session 的 MCP 连接 + per-session 凭据（或每用户 runtime，或宿主桥）。只换 header 不换连接仍可能并发串号。
- 当前内部桥已按 session 持 token；知识库 MCP 若要按用户鉴权，优先扩展桥的 per-user MCP client 池，而不是等 mcp-client 的 OAuth。

## PageAgent（阿里 page-agent）评估

- 结论：能接，但它是 **in-page GUI agent**（跑在网页里的 JS，文本化 DOM + LLM 决策），不是服务端/headless 浏览器；官方明确说是 client-side enhancement。

- 两条路径：
  - A. 嵌入 pc + WS 桥：只操作本系统同源 SPA；agent 加 `page_operate` 工具，经 WS 把指令发给浏览器里的 PageAgent；LLM key 走 `/agent/llm` 代理，不落浏览器；安全上用 `customTools` 去掉 `execute_javascript`、`maxSteps` 10~15、`transformPageContent` 脱敏、提交/删除走 `ask_user` 确认。需要新增 WS 服务 + 浏览器客户端 + PageAgent 封装，尚未实现。

- 已在 `agent/mcp.config.example.json` 加了 disabled 的 `page-agent` 示例（`npx -y @page-agent/mcp`，独立 `PAGE_AGENT_LLM_KEY`），`.env.example` 同步；README 增加评估章节。

## 长期记忆（自建，per-user）

- 调研结论：dsh **没有内置记忆模块**（`@deepseek-ai/*` 250 个包无 memory；仓库里只有 `docs/user/guide/mcp-memory.md`）。
  官方方案是接第三方记忆 MCP：Memorix / `@modelcontextprotocol/server-memory` / Engram，都是 stdio + 单数据目录。
  这三个都是进程级单库，我们单 runtime 多用户会串号，所以不用。
- 实现：`agent/src/memory.ts`（Map<usrId, MemoryItem[]>，落 `.dsh/memory.json`，原子写 + 300ms debounce）。
  - 每用户上限 300 条、单条 500 字、tags ≤ 8；同文本重复保存只更新 updatedAt/tags。
  - 敏感内容拦截：JWT / `Bearer xxx` / `password=` / `密码是`。
  - `digest()` 生成 `<user_memory>` 块，最多 10 条 / 1500 字。
- 工具：`memory_save` / `memory_search` / `memory_list` / `memory_forget`，走内部桥按 sessionId→usrId。
- 首轮注入：`index.ts` 在 appendTranscript 之后判断 `readTranscript().length === 1`，把 digest 拼到 prompt，
  转录只存用户原文（前端看不到前缀）。
- 技能 `memory-usage`：何时保存/不保存、去重、冲突清理、检索与忘记。
- 配置：`AGENT_MEMORY=true`、`AGENT_MEMORY_DIGEST_LIMIT=10`。
- 实测：会话 A “记住：我习惯用表格看数据，不要用饼图” → memory_save 成功；新会话 B 直接答出“表格、不喜欢饼图”，无工具调用；转录首条仍是原文；单测确认去重、隔离、敏感拦截。
