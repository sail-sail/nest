# 长期记忆

## 什么时候保存

用户明确要求记住时，必须调用 `memory_save`：

- "记住：我只看华东区的数据"
- "以后报表都用表格，不要用图"
- "我是财务，主要看订单和发票"

用户在对话中**稳定地**表达偏好、身份、约定，也可以主动保存：

- 反复纠正同一个格式（"不要用饼图"）
- 说明自己的角色、负责的业务范围
- 约定固定的输出规范（"金额都按万元"）

## 什么时候不要保存

- 密码、token、手机号、身份证、银行卡、密钥 —— 工具会直接拒绝。
- 一次性的任务细节（"这次查 2026-10 的订单"）—— 属于当前会话上下文。
- 从数据库查到的业务数据本身 —— 需要时重新查，别把结果当记忆。
- 你不确定是否长期有效的信息 —— 先不写，等用户确认。

## 写法

一句话、第三人称、可独立理解：

```json
{ "text": "用户偏好用表格展示数据，不喜欢饼图", "tags": ["偏好", "报表"] }
```

- `tags` 选 1~3 个稳定分类：偏好、身份、格式、业务范围。
- 重复保存同一件事会更新原条目，不会产生两条。
- 内容有冲突时（比如"以后用折线图"推翻了"不要图"），保存新记忆后，用 `memory_forget`
  删掉旧的那条，避免模型拿到互相矛盾的记忆。

## 检索

- 每个新会话的**第一轮**会自动注入最近 10 条记忆（`<user_memory>` 块）。
- 注入的可能不全，涉及具体细节时用 `memory_search` 搜关键词。
- 用户问"我之前说过什么 / 你还记得吗"时，先 `memory_search`，不要凭空猜。
- `memory_list` 用来核对到底存了哪些。

## 清理

- 用户说"忘掉 X"：`memory_forget({ query: "X" })`。
- 用户说"清空记忆"：`memory_forget({})`，执行前复述一次影响范围。
- 删除后告诉用户删了几条，不要假装已删。
